# Strmora（流幕）v1.0 开发计划与需求基线

状态：用户已批准启动 P0。创建日期：2026-10-28（Asia/Shanghai）。

本文件来自立项初始需求、V0.2～V0.7 修订及本聊天最终开发计划。后续实现必须与本文件核对；新增功能和需求变更先更新本文件并记录用户确认，不得通过实现自行改变需求。执行进度见 ../verification/p0-progress.md。

## 1. 定位与技术方案

自部署媒体管理 Web 应用，目标 10 人以内、约 30 台设备。独立提供 Emby API，不依赖 Emby Server。

- 名称 Strmora（流幕）；仓库名 strmora；标准 AGPL-3.0，免费、公开源码、社区维护。
- Go 单体服务，标准库与轻量路由；React + TypeScript + Vite 管理界面。
- SQLite、WAL、本地持久化、短事务和批量写入；不强制 Redis、PostgreSQL、消息队列服务。
- 输入 Local、OpenList API、通用 WebDAV；用户自行配置 TMDB API Key。
- Docker Compose 优先，后续跨平台二进制。数据库、STRM、元数据、日志、配置路径分别可设。
- 播放器目标 Infuse、VidHub、网易爆米花；兼容声明必须记录被测版本和真实结果。

## 2. 固定范围

选择源 → 扫描或目录树 → TMDB → 人工确认或自动规则 → 标准化和归类 → STRM、字幕、索引 → WebDAV 同步 → Emby 浏览和播放。

- SQLite 保存稳定身份、当前路径、元数据索引、任务、输出映射、同步状态及用户个人状态。
- STRM 是真实文件，包含用户配置的 URL 前缀、固定路径与最终媒体路径拼成的完整 URL。
- 远端仅同步 **STRM、对应字幕、分层 Markdown**。远端 WebDAV 播放器自行刮削。
- NFO、图片及其他刮削信息独立保存在本地，与作品一一映射；不开发媒体刮削信息导出功能，不向远端批量传输 NFO/图片。
- Emby API 读取自身索引，并定位和读取对应 STRM 的完整 URL。视频由播放器访问源，Strmora 只提供播放信息和必要的鉴权、302；无视频代理回退。
- 首版不做内置 WebDAV 服务、FFprobe、Direct Mode、视频转码/代理、字幕转换/烧录/OCR、DLNA、直播、下载器、内建播放器、分布式节点。
- 不登录 115、不保存 115 Cookie、不主动导出 115 目录树；SMB、S3、原生网盘驱动以后再评估。

## 3. 模块布局

cmd/strmora 启动；internal/config 配置；database 迁移/事务/备份；auth 用户设备与 MFA；sources 三种源适配器；inventory 扫描/目录树/快照；metadata TMDB；organizer 模板和整理；jobs 持久队列限流；exports 文件成果；sync 远端推送；emby 协议；admin 管理 API；web React；docs 文档。

适配器统一读能力并声明写入、批量操作能力，不假设通用 WebDAV 支持多文件单请求移动。

## 4. 媒体身份与数据库

作品 → 季度/逻辑单集；作品或单集 → 版本 → 有序片段 → 源文件；源文件 → STRM 和字幕；用户 → 观看状态和播放会话。

核心数据：源/限流组、源条目/快照、作品/季度/单集、版本/片段/文件关联、元数据/资源、计划/逐对象操作、输出/变更事件、各目标同步记录、用户/设备/会话。

内部稳定 ID 不使用路径或 TMDB ID 充当唯一主键。Strmora 改名移动不改变作品 ID 或进度。人工匹配普通扫描时继续有效；历史可配置保留和清理。重新刮削只更新本地元数据及 Emby 展示，不自动改源。

## 5. 媒体源和目录树

管理员配置连接、类型（电影/电视剧/其他）、源路径、默认目标、分类、排除、扫描时间、限流组和只读/可写权限。动漫/综艺/纪录片是用户分类，不与电影/电视剧底层类型混淆。

运行模式：只读；计划确认执行；自动整理独立开关且默认关闭。OpenList API 首版优先用于读取和修改，WebDAV 通用兼容。

目录树：匹配已有 TXT（默认名称包含“目录树”），手动/定时读取或导入，**完整下载本地再解析和比对**；界面翻页不请求 115。下载进入限流队列。

真实样本：1,590,070 字节，UTF-16 LE BOM，13,079 行（根节点 + 13,078 子节点）；根 `|——根目录`，子节点 `| |-` 等；最大子节点前缀深度 6，存在视频、字幕、图片，无已发现的独立完成标记。P0 实际解析发现 17 行重复路径：保留原条目并报告歧义，歧义未解决不得据此执行破坏性差异或整理。样本源地址不写入仓库，避免公开私人媒体路径。

步骤：临时文件完整下载 → 原子保存候选 → 严格解码 UTF-16 BOM/UTF-8 → 层级栈还原名称和相对路径 → 用户映射树根到源路径/覆盖子路径 → 校验 → 本地差异 → 提交有效结果。

- 空行跳过；中文/空格/标点原样保留。不能因扩展名就确定所有叶子类型，无法确定保留待定。
- 下载/解码/层级失败不提交，不删除；可解析不等于上游导出完整，必须显示覆盖和差异。
- 一次完整有效且覆盖明确的扫描可确认缺失，无须强制二次扫描。失联/鉴权/限流不视为空目录。
- 自己的修改直接回写数据库，不全量复扫；父目录成功后事务更新所有已知子路径。
- 最近两个有效快照滚动保留；未完成操作/同步独立保留。
- 旧快照不能覆盖已确认的新路径；冲突保护受影响路径并按需核验。文件名时间仅作线索。
- 外部改名按旧删新加；不为同路径同名替换加入复杂检测。

## 6. 刮削和命名

优先明确 TMDB ID → 作品文件夹名（散文件用文件名）→ 名称/年/季集/版本/part → TMDB 候选和详情 → 符合规则自动接受，歧义人工确认。

语言、备用语言、成人开关、分级地区可设；字段和分级中文解释可点击/悬停查看；未知不猜。电视剧先识别作品，不逐集独立搜索。“其他内容”不自动 TMDB，保留名称，允许人工标题图片说明。

电影目录/文件、电视剧目录/季度/单集模板独立；字段顺序和分隔符可设；默认 `名称 (年份)`；解释并允许保留 version、part、ext。扩展名合法保留，part 标准化如 `名称 - part1.mkv`。

合集自动归类可开关，最小电影数量默认 2；本地不同电影计数，不以版本计数。一个作品目录/作品级 NFO/多版本。支持 S01E01-E02，一个文件关联多个逻辑集，不承诺无时间边界的精确跳播；电影/单集多个 part 有序关联；不为连续播放拼接转码。

季度使用 Season 00/01…标准编号，显示别名独立；特别篇最前，之后编号排序。分集组人工选择，并预览本地文件→TMDB 分集对照，确认后重排。extras 不直接当正片，歧义人工处理。未探测技术参数保持未知，文件名推断标注来源。

## 7. 整理与恢复

两阶段：标准化（外层→季度→文件及字幕）和最终归类（默认→人工目标组）。管理员逐个/批量覆盖目标，有人工目标直接去该目标，不绕默认目录。

- 已有电影目录整体移动；散电影在最终目标创建外层目录再移入；电视剧整体移动。
- OpenList 同源目录+目标目录分组；默认批次 50，用户可调，“全部”自动拆批；50 非已确认 115 通用限额。
- WebDAV 逐项执行；批量结果逐对象记录，HTTP 成功不等于全部成功。
- 默认不覆盖冲突，执行前重验前置条件；记录原/当前/计划路径和依赖。
- 状态：待执行/执行中/确认成功/失败/结果不明确。重启和超时先核验再重试。
- 取消立即停止新提交，等待/核验已发出请求；初始等待 1～3 秒并非完成保证；展示已变更/未变更/不明确，用户选择停止或回退。
- 回退按依赖反向执行，记录结果和冲突，不承诺全局事务；清理不删除恢复/同步仍引用的记录。

## 8. 限流与任务观测

目录读取/核验/建目录/改名/移动/字幕下载均过调度器，多媒体源可共享组。配置 QPS、并发、修改间隔、批次、退避、冷却、手动暂停、严格保护模式。

115 项目初始建议 0.5 QPS、并发 1、修改间隔 10 秒、批次 50，管理员可调，不是官方安全额度。鉴权与限流区分，连续异常暂停不无限重试。只报告自身可观测请求成本，不声称控制账号全部流量。

## 9. 输出与同步

STRM 完整 URL 正确编码中文空格特殊字符。默认镜像源确认后的结构，允许自定义源→输出映射/结构；换根目录只更新映射，不重新刮削。

字幕在最终整理完成后下载，同 STRM，记录版本/语言/格式/来源/状态；保留原始 SRT/ASS/SSA/VTT/SUP/SUB+IDX；不重复下载未变化文件，不清理用户文件。

`_STRMORA_INDEX.md`：根与各管理层生成，具体电影目录和具体季度目录不生成；含目录树/更新时间/数量/近期变化，可配置展开和历史条数。

远端仅 STRM/字幕/Markdown，首次和增量/删除/重试/冲突/恢复；只删自身管理输出，不删无关文件。各目标独立状态，文件成功后才记完成；STRM/字幕成功后发布依赖它们的 Markdown。SQLite 变更任务+本地安全替换恢复跨文件/数据库中断。

## 10. Emby、用户与安全

接口覆盖服务器信息、密码登录/设备 token、授权库、浏览/搜索/排序/分页、作品/季集/图、最近添加/继续观看/合集、PlaybackInfo/多版本/302、播放开始进度停止、已看/收藏、外部字幕元信息和原文件交付。

播放：数据库定位版本→读取 STRM→完整 URL→兼容媒体信息→必要鉴权302→客户端访问源；Range 在最终源验证。SUP、合并剧集、part 连播逐客户端实测，不用转码兜底。不上报进度不推测、不做私有客户端适配。

管理员密码+TOTP/Passkey；普通用户密码→设备 token，只读授权媒体、可写自己进度收藏已看。支持设备撤销、失败限速/临时封禁、恢复码、本地解封、审计。信任明确代理、保护凭据、防路径穿越。

默认管理 /admin，自定义字母数字路径；Emby 根/默认/自定义前缀通过实测确定组合，避免路由冲突；随机路径不能替代认证。无独立复杂 STRM 播放 token 体系。

## 11. 开发阶段与验收

| 阶段 | 任务 | 验收 |
|---|---|---|
| P0 基础和协议 | Go、SQLite迁移、合成媒体、真实目录树解析、最小 Emby 登录图片播放进度字幕 | 样本解析；三款客户端分别实测记录缺失能力；不能用自动化通过代替真实兼容 |
| P1 索引 | 三源、配置、限流、扫描、下载、快照差异、权限 | 失联不误删，重复和旧快照正确处理 |

| P4 输出同步 | STRM、独立NFO图片、字幕、Markdown、WebDAV | 正确本地成果；远端范围正确；失败可恢复 |
| P5 完整服务 | Emby补齐、用户授权、MFA、路由、工作台监控 | 全流程管理；权限隔离；真实播放器端到端 |

顺序 P0→P1→P2→P3→P4→P5→P6，界面随功能交付。P0 后再根据实际投入估算，不虚设日期。

## 12. 验证与变更纪律

必要测试：真实 TXT/编码/空行/层级/损坏；部分成功超时重启取消回退旧快照；URL字幕Markdown同步删除边界；身份和权限；三客户端实际版本；约30会话+后台任务数据库竞争。HTTP200不等于功能成功。

P0 使用合成媒体和测试数据库，不修改源，不复制私人目录树到公开仓库。客户端无法在此环境运行时明确记为待测，P0 不宣称全部验收。测试只覆盖必要行为和风险。

需求变更必须记录用户新指令、受影响章节和验收调整；进度记录实现与待验收分别标注。Git提交/推送/发布按用户授权执行，不因计划自动对外发布。
